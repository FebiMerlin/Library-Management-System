## Шаг 3. Репозиторий и CI — вкладки 3 и 4

*(Открыть вкладку 3 — Actions.)*

> Это сборочная инфраструктура — CI, непрерывная интеграция. Каждое изменение, попадающее в репозиторий, GitHub автоматически собирает и тестирует. *(Кликнуть верхний прогон.)* Пять заданий: Ubuntu с компилятором GCC, Ubuntu с Clang, Windows с компилятором Microsoft, macOS — и отдельно проверка форматирования кода. Все зелёные. Сборка идёт в строгом режиме: любое предупреждение компилятора считается ошибкой.
>
> CI реально ловил ошибки: в истории видно три красных прогона. Компилятор GCC на Linux нашёл потенциальное переполнение буфера, которого не видел компилятор на Windows; затем выяснилось, что на Windows новая версия Visual Studio; затем — что тесты запускались раньше, чем собирались файлы. Всё исправлено, и именно для этого CI нужен: ошибка видна до того, как код попал к заказчику.

*(Открыть вкладку 4 — PR №1.)*

> Работа велась по регламенту: основная ветка защищена, изменения попадают в неё только через pull request — запрос на слияние с проверкой. Вот основной PR: тринадцать коммитов, каждый с понятным названием — «ревизия», «сборка», «тесты», «CI». Внизу — зелёные проверки, после которых он влит.

## Шаг 4. Журнал ревизии — вкладка 5

> Это журнал ревизии исходного кода. Тридцать пять проблем в четырёх разделах: ошибки логики, отсутствующие функции, архитектура, инфраструктура. У каждой — серьёзность, место в исходном файле, как воспроизвели, как исправили и какой тест это подтверждает. Три примера.
>
> Первая, 1.1: добавление книг не работало вообще. Счётчик книг при старте ставился в максимум, поэтому пункт «добавить книгу» всегда отвечал «лимит достигнут». Исправлено: лимит проверяется по реальному числу книг; есть тест.
>
> Вторая, 1.2, критическая: при выборе книги вводимый номер не проверялся и напрямую использовался как индекс массива. Ввод 999 — чтение памяти за пределами массива, неопределённое поведение, в реальных системах через такое взламывают программы. Исправлено: книга выбирается по уникальному номеру ISBN и ищется в списке; нет — вежливый отказ. Тест подаёт несуществующие номера, ноль и минус один.
>
> Третья, 2.1, тоже критическая: данные не сохранялись. Все студенты и книги жили только в памяти — закрыл программу, всё исчезло. Это стало нашей первой новой функцией: состояние пишется в файл после каждой операции и загружается при старте, запись безопасная — через временный файл. Девять тестов на хранение плюс один сквозной, который запускает программу дважды и проверяет, что данные пережили перезапуск.
>
> Не исправлены осознанно две: полноценная авторизация с хешированием паролей — вынесена за рамки ТЗ, об этом вопрос к вам; и отсутствие лицензии у исходного репозитория — организационный момент, авторство указано.

## Шаг 5. Сборка и демонстрация — Шарыгин

> Теперь сборка с нуля и демонстрация пяти функций — Шарыгин.

*(Шарыгин работает по своему сценарию. Твои реплики по ходу:)*

- Когда сборка закончилась строкой `100% tests passed, 0 tests failed out of 65`:
  > Это и есть требование «проверка тестами во время сборки»: тесты запустились сами как последний шаг сборки. Если бы хоть один упал — сборка считалась бы неудачной.
- На поиске книг (`stroustrup`):
  > Функция три — поиск по названию, автору или ISBN без учёта регистра.
- На четвёртой книге, когда отказ:
  > Функция два — ограничение три книги на студента.
- На выписке:
  > Функция пять — история операций по счёту: открытие, пополнения, выдачи, возвраты, штрафы.
- На `cat demo.dat`:
  > Функция один — данные в текстовом файле, формат читаем и документирован.
- На запуске с другой датой и возврате со штрафом:
  > Данные загрузились из файла. Функция два — срок выдачи десять дней, штраф доллар в день, здесь семнадцать дней — семь долларов. Дату подменяем ключом, чтобы не ждать десять дней.
- На удалении книги и закрытии счёта:
  > Функция четыре — удаление книги и закрытие счёта с возвратом остатка и залога.
- На вводе `abc` и `99`:
  > Обратите внимание: буквы и число вне меню отвергаются, программа переспрашивает. В оригинале это была критическая ошибка 1.3 — на буквах программа молча завершалась. Есть автоматический тест.
- На вводе пароля `password`:
  > Пароль больше не зашит в код — задаётся снаружи через переменную окружения.
