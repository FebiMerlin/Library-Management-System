## 2. Что за проект — двумя абзацами

Исходник: консольный учёт библиотеки, один `main.cpp`, глобальные массивы, `char[50]` вместо строк, `cin >> x` без проверок, пароль `"password"` в коде, данные не сохраняются. Ревизия нашла 35 проблем (`docs/ISSUES.md`).

Что стало: код разделён на **ядро** `lms_core` (`include/lms/`, `src/core/` — вся логика, никакого ввода/вывода, поэтому тестируется) и **консоль** `lms` (`src/cli/` — меню, проверка ввода). Деньги — целые центы (`Money`), даты — дни от 1970 (`Day`), правила библиотеки — в `Config`. Ошибки возвращаются как `Result`, а не печатаются из ядра. Тесты — `tests/` (GoogleTest + скрипты, которые гоняют настоящий бинарник).

## 5. Вопросы по коду, которые могут задать

- **Где главная логика?** `src/core/library.cpp`, класс `Library`: `addBook`, `createAccount`, `issueBook`, `returnBook`, `closeAccount`, `searchBooks`, `history`. Заголовок — `include/lms/library.h`.
- **Как хранятся данные?** `src/core/storage.cpp`: текстовый файл, табуляция как разделитель, строки `BOOK` / `STUDENT` / `TX`. Запись атомарная: сначала во временный файл, потом переименование. При загрузке всё проверяется, битый файл — понятная ошибка с номером строки. Формат описан в `docs/FEATURES.md`.
- **Почему деньги в центах?** `double` даёт ошибки округления (0.1 + 0.2 ≠ 0.3); есть тест `Money.NoFloatingPointDrift`.
- **Как проверяется ввод?** `src/cli/console.cpp`, класс `Console`: всё читается построчно, разбирается, при ошибке переспрашивается. В исходнике `cin >> int` на буквах ломал поток.
- **Какие баги исходника исправлены?** Три главных: добавление книг никогда не работало (счётчик стартовал с максимума — `Books.LimitAppliesOnlyWhenFull`); чтение за границей массива при выборе книги (`Loans.IssueRejectsUnknownStudentOrBook`); неудачная регистрация оставляла мусор в массивах (`Students.FailedCreationLeavesNoTrace`). У каждого бага есть тест, который его воспроизводит.
- **Что такое `Result`?** Структура `{ok, error}`, которую возвращает каждая операция ядра. Консоль печатает `error`, ядро ничего не печатает — поэтому его можно тестировать.
- **Почему `--today`?** Чтобы показать штраф за просрочку, не ожидая 10 дней; в обычной работе дата берётся с часов.
- **Где тесты консоли?** `tests/scripts/*.in` — ввод, `*.expect` — строки, которые должны появиться в выводе; `tests/run_script.cmake` запускает бинарник. Тест `persistence` запускает программу дважды и проверяет, что данные пережили перезапуск.
