## 1. Исходные данные

На вход передан проект [abdulsamie10/Library-Management-System](https://github.com/abdulsamie10/Library-Management-System): консольная система учёта библиотеки на C++, один файл `main.cpp` (312 строк), без системы сборки, тестов и хранения данных. Результаты ревизии — в `docs/ISSUES.md`.

## 2. Цели работ

1. Провести ревизию кода и зафиксировать перечень проблем в журнале.
2. Описать сборку проекта при помощи CMake.
3. Собрать проект.
4. Написать тесты.
5. Реализовать 5 функциональных возможностей (фичей).
6. Обеспечить проверку проекта тестами во время сборки.
7. Развернуть инфраструктуру: трекер задач, сборочную инфраструктуру (CI), git-репозиторий, IDE.

## 3. Требования к продукту

### 3.1. Функциональные требования

| ID | Требование | Приоритет |
|---|---|---|
| FR-1 | Все функции исходного проекта сохраняются: вход администратора по паролю, добавление/редактирование/просмотр книг, список студентов, регистрация студента, баланс, пополнение, выдача книги. | Обязательно |
| FR-2 | Ошибки из `docs/ISSUES.md` разделов 1–2 устранены (кроме явно исключённых в п. 6). | Обязательно |
| FR-3 | **F1. Хранение данных.** Состояние (книги, студенты, история) сохраняется в файл и восстанавливается при следующем запуске. Файл текстовый, формат документирован. Повреждённый файл не приводит к падению — выводится понятная ошибка. | Обязательно |
| FR-4 | **F2. Возврат книг и штрафы.** Фиксируется дата выдачи; студент возвращает книгу; при просрочке более 10 дней начисляется штраф $1/день; не более 3 книг на студента; отчёт администратора по просроченным книгам. | Обязательно |
| FR-5 | **F3. Поиск книг** по подстроке названия, автора или ISBN без учёта регистра, с фильтром «только доступные». | Обязательно |
| FR-6 | **F4. Удаление книги и закрытие счёта.** Удалить можно только невыданную книгу; закрыть счёт можно только без книг на руках, при закрытии возвращается баланс и залог $30. | Обязательно |
| FR-7 | **F5. История операций (выписка)** по счёту студента: открытие, пополнения, выдачи, возвраты, штрафы, закрытие; доступна студенту и администратору. | Обязательно |
| FR-8 | Любой некорректный ввод (не число, число вне диапазона, пустая строка) не ломает программу — запрос повторяется. | Обязательно |
| FR-9 | Пароль администратора не хранится в исходном коде. | Обязательно |
| FR-10 | Денежные суммы отображаются с двумя знаками после запятой и не подвержены ошибкам округления. | Обязательно |

### 3.2. Требования к сборке и тестированию

| ID | Требование |
|---|---|
| BR-1 | Сборка описана в CMake (≥ 3.16), стандарт C++17, без зависимости от Qt/Boost/системных библиотек, кроме стандартной. |
| BR-2 | Проект собирается на Linux (GCC ≥ 9, Clang ≥ 10), Windows (MSVC 2022, MinGW-w64) и macOS одной командой `cmake --preset <name> && cmake --build --preset <name>`. |
| BR-3 | Сборка с включёнными предупреждениями (`-Wall -Wextra -Wpedantic …` / `/W4`) проходит без предупреждений; в CI предупреждения — ошибки. |
| BR-4 | Тесты: модульные (GoogleTest) для бизнес-логики и сквозные (CTest) для консольного интерфейса. Перечень — `docs/TESTS.md`. |
| BR-5 | Тесты выполняются **в процессе сборки** (цель по умолчанию зависит от прогона CTest); упавший тест = упавшая сборка. Отключается опцией `LMS_RUN_TESTS_ON_BUILD=OFF`. |
| BR-6 | CI (GitHub Actions) собирает и тестирует каждый push и pull request на трёх ОС. |
| BR-7 | Код отформатирован по `.clang-format`; проверка форматирования — часть CI. |

### 3.3. Требования к инфраструктуре

| ID | Требование |
|---|---|
| IR-1 | Git-репозиторий на GitHub (форк исходного, с сохранением истории автора); при необходимости — зеркало на ресурсах кафедры (Gitea). |
| IR-2 | Трекер задач с назначением исполнителей, сроками, процентом выполнения и канбан-доской с ≥ 4 состояниями. Все участники заведены. Все задачи проекта заведены до начала работ. |
| IR-3 | Сборочная инфраструктура: GitHub Actions (основная) и/или самостоятельный раннер на ресурсах кафедры (docker-compose в `infra/`). |
| IR-4 | IDE: единая рекомендованная конфигурация (VS Code + CMake Tools + clang-format) в репозитории; альтернатива — CLion. |

Обоснование выбора — `docs/INFRASTRUCTURE.md`.

## 6. Ограничения и допущения

* Полноценная аутентификация (учётные записи, хеширование паролей) **не входит** в объём: пароль администратора берётся из переменной окружения `LMS_ADMIN_PASSWORD`; студент идентифицируется номером зачётки. Согласовать с Заказчиком.
* Хранилище — один текстовый файл; одновременная работа нескольких экземпляров программы не поддерживается.
* Интерфейс — консольный, язык интерфейса английский (как в исходном проекте); документация — на русском.
* Исходный репозиторий не имеет лицензии; работа ведётся как учебный форк с указанием автора.
