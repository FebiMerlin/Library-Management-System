# Инфраструктура проекта: выбор и обоснование

Документ готовит менеджер проекта для согласования с DevOps и Заказчиком (пункты «подобрать вариант…, согласовать…, привести обоснованные аргументы» из задания). Для каждого компонента: варианты, выбор, обоснование, требуемые ресурсы, сроки, работы.

## 1. Трекер задач

### Требования из задания
Заведение задач разным пользователям, сроки, **процент выполнения**, канбан-доска с несколькими состояниями.

### Рассмотренные варианты

| Вариант | Проценты | Канбан | Сроки | Размещение | Плюсы | Минусы |
|---|---|---|---|---|---|---|
| **GitHub Projects + Issues** | нет встроенного поля % (можно кастомное поле Number) | да | да | облако GitHub | рядом с кодом, PR закрывают задачи, ноль администрирования | нет self-hosted, % — только вручную через кастомное поле |
| **Vikunja** (self-hosted) | **да, поле «Percent done»** | да | да (start/end/due) | Docker на ресурсах кафедры, ~200 МБ RAM | лёгкий, есть Gantt, таблица, канбан; открытый код (AGPL); импорт из Trello/Todoist | нет интеграции с git-коммитами «из коробки» |
| YouTrack (JetBrains) | да | да | да | облако (бесплатно до 10 польз.) или self-hosted, ≥ 2 ГБ RAM | мощный, отчёты | тяжёлый для 3 человек; self-hosted требует Java и 2+ ГБ |
| Jira Cloud | да (через time tracking) | да | да | облако | стандарт индустрии | требует регистрации организации, избыточен |
| Taiga / OpenProject | да | да | да | self-hosted, ≥ 2–4 ГБ RAM | полноценные | тяжёлые в развёртывании |
| Trello | нет | да | да | облако | простой | нет процентов, нет self-hosted |

### Выбор
**Основной — Vikunja** (self-hosted на ресурсах кафедры, `infra/docker-compose.yml`): единственный лёгкий вариант, где процент выполнения — штатное поле задачи, а не костыль. **Резервный — GitHub Projects** (если кафедра не выделяет сервер): задачи заводятся как Issues, % — кастомное поле «Progress», канбан — представление Board с колонками Backlog / To do / In progress / Review / Done. Скрипт `scripts/create_github_issues.py` переносит задачи из `docs/tracker_tasks.csv` в Issues автоматически.

### Ресурсы, сроки, работы (для согласования с DevOps и кафедрой)
* **Ресурсы:** виртуальная машина или контейнерный хост кафедры: 1 vCPU, 1 ГБ RAM, 5 ГБ диска, Docker ≥ 24, доступ по HTTP(S) из сети университета. Достаточно даже Raspberry Pi.
* **Работы DevOps:** запуск `docker compose up -d` (Vikunja + PostgreSQL), создание проекта «LMS», заведение 3 пользователей + Заказчика с правами чтения, настройка канбан-колонок, импорт задач.
* **Срок:** 1 рабочий день (2 ч работы + ожидание доступа к серверу).
* **Если сервера нет:** GitHub Projects — 1 ч, никаких ресурсов.

## 2. Git-репозиторий

| Вариант | Плюсы | Минусы |
|---|---|---|
| **GitHub (форк исходного)** | сохраняется связь с оригиналом и история автора; бесплатный CI (Actions); PR-ревью; Заказчик видит всё без регистрации | зависимость от внешнего сервиса |
| Gitea на ресурсах кафедры | полный контроль, работает без интернета | нужен сервер; нет бесплатных раннеров |
| GitLab self-hosted | всё в одном | ≥ 4 ГБ RAM, тяжёл для учебного проекта |

**Выбор:** GitHub как основной (форк `abdulsamie10/Library-Management-System`), **Gitea как зеркало** на ресурсах кафедры (тот же `infra/docker-compose.yml`, профиль `git`), если Заказчик требует размещения на кафедре. Зеркалирование — `git push --mirror` из CI или встроенная функция Gitea «Mirror».

Ветки: `main` (защищённая, только через PR), `feature/<задача>`, `fix/<задача>`. Подробнее — `docs/REGULATIONS.md`.

## 3. Сборочная инфраструктура (CI)

### Требования
Сборка и прогон тестов на каждый push/PR; поддержка Linux и Windows; результат виден Заказчику.

| Вариант | Плюсы | Минусы |
|---|---|---|
| **GitHub Actions** | бесплатно для публичных репо; готовые образы Ubuntu/Windows/macOS с GCC/Clang/MSVC/CMake; ноль администрирования | нет контроля над раннерами |
| Gitea Actions (self-hosted runner) | совместим с синтаксисом GitHub Actions — тот же `ci.yml`; работает на сервере кафедры | нужен хост с Docker; Windows-сборка требует отдельной Windows-машины |
| Jenkins | универсален | Java, ≥ 2 ГБ RAM, много ручной настройки |
| GitLab CI | удобен | только с GitLab |

**Выбор:** GitHub Actions (`.github/workflows/ci.yml`, матрица Ubuntu GCC/Clang + Windows MSVC + macOS). На ресурсах кафедры — **Gitea + act_runner** с тем же workflow-файлом (профиль `ci` в `infra/docker-compose.yml`); образ сборщика — `infra/Dockerfile.build` (Ubuntu 24.04 + GCC 13 + Clang 18 + CMake + Ninja).

### ОС и состав сборочной инфраструктуры
* **ОС сборочного хоста:** Ubuntu Server 24.04 LTS (поддержка до 2029, GCC 13 и CMake 3.28 в репозиториях, Docker из официального репозитория).
* **Состав:** Docker 24+, Gitea 1.22, act_runner 0.2, образ `lms-builder` (см. Dockerfile), Vikunja 0.24, PostgreSQL 16.
* **Ресурсы:** 2 vCPU, 4 ГБ RAM, 20 ГБ диска (сборка GoogleTest + проекта ≈ 1 мин на 2 ядрах).
* **Работы DevOps:** установка Docker, `docker compose --profile git --profile ci up -d`, регистрация раннера, защита ветки `main`, настройка зеркала.
* **Срок:** 1–2 рабочих дня.

## 4. IDE и инструменты разработчика

| Вариант | Плюсы | Минусы |
|---|---|---|
| **VS Code + CMake Tools + clangd/cpptools + clang-format** | бесплатно, кроссплатформенно, конфигурация в репозитории (`.vscode/`), поддержка `CMakePresets.json` | требует настройки расширений (автоматизировано через `extensions.json`) |
| CLion | лучшая интеграция с CMake, бесплатно для студентов | тяжёлый, лицензия по студенческому email |
| Visual Studio 2022 Community | нативный MSVC, открывает CMake-проекты напрямую | только Windows |
| code-server (VS Code в браузере) на ресурсах кафедры | единая среда для всех, ничего не ставить локально | нужен сервер, задержки |

**Выбор:** VS Code (единая конфигурация в репо) — основной; CLion / VS 2022 допускаются, т.к. все работают через `CMakePresets.json`. **Размещение на кафедре:** code-server (профиль `ide` в `infra/docker-compose.yml`) — по требованию Заказчика; ресурсы 1 vCPU, 2 ГБ RAM на пользователя.

Правила оформления кода и регламент — `docs/REGULATIONS.md`.

## 5. Сводка для согласования с Заказчиком

| Компонент | Выбор | Размещение | Ресурсы кафедры | Срок |
|---|---|---|---|---|
| Трекер | Vikunja (резерв: GitHub Projects) | Docker на сервере кафедры | 1 vCPU / 1 ГБ / 5 ГБ | 1 день |
| Git | GitHub (форк) + зеркало Gitea | GitHub + сервер кафедры | входит в тот же хост | 0.5 дня |
| CI | GitHub Actions + Gitea act_runner | GitHub + сервер кафедры | 2 vCPU / 4 ГБ / 20 ГБ (общий хост) | 1–2 дня |
| IDE | VS Code (конфиг в репо); code-server по требованию | локально / сервер кафедры | 1 vCPU / 2 ГБ на пользователя | 0.5 дня |

**Минимальный вариант без ресурсов кафедры:** GitHub (репо + Projects + Actions) + VS Code локально — разворачивается за 2 часа и полностью покрывает требования задания, кроме слова «на ресурсах кафедры». Все файлы для варианта «на кафедре» подготовлены в `infra/`.
